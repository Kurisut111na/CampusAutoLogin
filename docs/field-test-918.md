## 2. ⭐ 最先做：F12 抓包（决定 QueryEscape 真相，5 分钟）

**这一项优先级最高**——它决定一个悬而未决的代码分歧，且只有真实校园网能做。

1. 浏览器开无痕窗口，F12 → Network 面板
2. 在 Portal 页面**正常登录一次**（用你自己的学号密码）
3. 找到登录请求（`eportal/portal/login` 或 `drcom/login`），看 **Query String Parameters**
4. 重点看两个参数的值形态：
   - `user_password`：裸 `+` `/` `=`，还是 `%2B` `%2F` `%3D`？
   - `user_account`：裸 `,0,学号@cmcc`，还是 `%2C0%2C...%40cmcc`？

**判定**：
- 浏览器发**编码形式**（`%2B` 等）→ 服务端会解码，转义安全，后续版本可重新加上
- 浏览器发**原始形式**（裸 `+`）→ 服务端不解码，**当前"不转义"的代码正确，永远不要改**
- [ ] 抓包结果：**原始 / 编码**（记下来）

## 3. 到校实测（按顺序做）

### 场景 A — 正常登录（核心，必测）
- [ ] 双击 exe → **窗口应立即出现**（修复前未认证网络下会白等 5 秒）
- [ ] 登录 → 托盘变绿 + 成功气泡 → 能正常上网
- [ ] **结果：通过 / 失败**

### 场景 B — 日志脱敏（必测）
- [ ] 打开 `%LOCALAPPDATA%\CampusAutoLogin\logs\<当天>.log`
- [ ] 搜索 `URL:` → 应看到 `user_password=***` 和 `upass=***`
- [ ] **整个日志文件里绝不能出现明文密码或 base64 密码**（出现即回归，截图）
- [ ] 主窗口日志面板里同样应是 `***`

### 场景 C — 更新检查（有网时补测）
- [ ] 联网状态下重启一次程序，日志应有 `Version check: current=0.2.1 remote latest=0.2.0 min=0.1.0`
      （本地版本已升到 0.2.1 故不弹更新框；**这行出现即证明 master 分支 URL 修复生效**）
- [ ] 未认证网络下启动没有这行是正常的（检查已改为异步 + 失败静默跳过）

### 场景 D — 配置持久化三连（新增，对应本次修复）
- [ ] **D1 退出不丢配置**：改一下用户名 → **立即**（2 秒内）右键托盘退出 → 重启确认已保存
      （修复前这里会丢最后一次修改）
- [ ] **D2 上次登录时间不虚增**：不登录，只改任意设置 → 看 `config.json` 的 `last_login_time`
      **应保持不变**（修复前每改一次设置就被刷成当前时间）
- [ ] **D3 密码损坏自愈**：把 `config.json` 里 `password` 的 base64 **改掉一个字符** → 启动
      → 密码框应为**空**、日志有 Warn → 重新输入密码登录成功
      （修复前：密文会被再加密一层，永久损坏）

### 场景 E — 断线重连（可选）
- [ ] 登录成功后关闭再打开 WiFi → 心跳报断开 → 自动重连成功
- [ ] **观察日志**：若出现"无法上网"重试，确认**最多重试 2 次后停下**，不是无限循环
